| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1  | Сайт отображает новому клиенту список доступных депозитов с актуальными ставками                                |              |
| F2  | Сайт позволяет клиенту подать заявку на депозит, оставив свой номер телефона и Ф. И. О. |              |
| F3  | Заявка на депозит отображается в системе кол-центра|              |
| F4  | Интернет-банк отображает клиенту список доступных депозитов с актуальными ставками и персонализированные ставки лично для него                                |              |
| F5  | Интернет-банк позволяет клиенту подать заявку на открытие депозита указав счёт и сумму депозита|              |
| F6  | АБС умеет автоматически расчитывать ставки по депозитам с учетом параметров клиента |              |
| F7  | АБС предоставляет информацию о ставке по депозитам сотрудникам бэк-офиса кредитов и депозитов|              |
| F8  | Клиент должен получить СМС-уведомления после подтверждения размера ставки и открытия депозита |              |
| F9  | Интернет-банк инициирует отправку СМС-уведомления клиенту для подтверждения создания заявки на депозит | Есть связанное требование R3 |
| F10 | Для создание заявки на открытие депозита клиент должен быть авторизован | В ином случае не будем знать, кому нужен депозит|
| F13 | Заявка на депозит доступна для просмотра сотрудникам кол-центра|Исходит из требования F3. В ином случае F3 лишено смысла|
| F14 | Клиент может запросить повторное СМС-уведомление для подтверждения заявки в интернет-банке спустя минуту, но не более 3х раз|Улучшает клиентский опыт. Не дорого в реализации|
| U   | Удобство использования (Usability) |              |
| U1  | Должна соблюдаться система дизайна приложений. Пользователи при работе должны видеть привычные цвета и брендированные элементы|              |
| U2  | Создать заявку на депозит можно на главном экране интернет-банка и сайта|Клиент будет знать, что такая функция есть. Ему не нужно будет загружать кол-центр и отделения запросами на открытие депозита|
| R   | Надёжность (Reliability)           |              |
| R1  | Все сервисы должны работать 24/7 |              |
| R2  | Все сервисы должны быть доступны в 99,9% случаев|    
| P   | Производительность (Performance)   |              |
| P1  | Отклик по всем операциям, совершаемым клиентом, должен быть максимально быстрым и занимать миллисекунды|              |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Решение должно быть задокументировано |              |
| +R  | + Ограничения (Restrictions)       |              |
| R1  | Чувствительные данные сайта необходимо защищать с помощью механизма шифрования трафика|              |
| R2  | Чувствительные данные интернет-банка необходимо защищать с помощью механизма шифрования трафика|              |
| R3  | Клиент подтверждает регистрацию заявки на открытия депозита в интернет-банке sms-кодом|              |
| R4  | Необходимо по возможности использовать технологии, которые уже внедрены в банке|Архитектурно-значимое требование|
| R5  | Новые технологии должны быть совместимы с имеющимися|Архитектурно-значимое требование|
| R6  | В качестве брокера сообщений лучше использовать kafka|Архитектурно-значимое требование|
| R7  | Избегать прямой работы интернет-банка с API АБС, чтобы не нагружать БД АБС|Архитектурно-значимое требование|
| R8  | В случае сбоев в ЦОД необходимо, чтобы сервисы интернет-банка были доступны и выдерживали требуемую нагрузку |Архитектурно-значимое требование|
| R9  | Желательно предусмотреть равномерное горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД|Архитектурно-значимое требование|
| R10 | АБС может масштабироваться только вертикально из-за своей базы данных|Архитектурно-значимое требование|
| R11 | Сотрудники бэк офиса обрабатывают заявки на открытие депозита через системы банка. Без формирования excel файлов и отправки писем друг другу|Архитектурно-значимое требование. Ускоряет решение заявок. Снижает человеческий фактор|
| R12 | Интеграционное взаимодействие межде банком и кол-центром партнера можно организовать только через передачу файлов |Архитектурно-значимое требование. Из условия 4го задания|
